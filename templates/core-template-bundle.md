# Kernbündel

Vier Vorlagen, die in keiner anderen Sammlung dieses Netzes liegen — drei davon für Pflichten, die **heute** anwendbar sind.

---

## 1 Praktikenprüfung (Art. 5)

Anwendbar seit **2.2.2025**. Einmal je Einsatzzweck, bei neuen Werkzeugen erneut.

**Einsatzzweck:** ___  **Werkzeug:** ___  **Geprüft am:** ___  **Geprüft durch:** ___

| # | Verbotene Praktik | Trifft zu | Begründung |
|---|---|---|---|
| 1 | unterschwellige oder manipulative Techniken, die zu Schaden führen | | |
| 2 | Ausnutzung von Schwäche wegen Alter, Behinderung, sozialer Lage | | |
| 3 | Sozialbewertung von Personen | | |
| 4 | Vorhersage von Straftaten allein anhand von Profilen | | |
| 5 | **ungezieltes Auslesen von Gesichtsbildern** aus dem Netz oder aus Überwachungsaufnahmen | | |
| 6 | **Emotionserkennung am Arbeitsplatz oder in Bildungseinrichtungen** | | |
| 7 | biometrische Kategorisierung zur Ableitung sensibler Merkmale | | |
| 8 | biometrische Echtzeit-Fernidentifizierung im öffentlichen Raum zu Strafverfolgungszwecken | | |

**Zu Nr. 6 besonders prüfen:** Funktionen, die Gespräche nach Stimmung auswerten — in Analysewerkzeugen für Vertrieb, Personal und Schulung verbreitet. Die Unterscheidung: Analyse von **Kundentexten** ist nicht von diesem Verbot erfasst; Bewertung von **Beschäftigten** oder Lernenden schon.

**Zu Nr. 5 besonders prüfen:** Werkzeuge zur Personensuche, Identitätsprüfung oder Anreicherung von Kontaktdaten.

**Ergebnis:**

- [ ] Kein Treffer. Prüfung beendet, Ergebnis mit Datum abgelegt.
- [ ] Treffer bei Nr. ___. **Betrieb einstellen.** Entscheidung dokumentiert am ___ durch ___. Alternativen geprüft: ___

Ein Treffer lässt sich nicht durch Dokumentation heilen. Die Dokumentation belegt, dass die Prüfung stattgefunden und zu einer Entscheidung geführt hat.

## 2 Schulungsnachweis (Art. 4)

Anwendbar seit **2.2.2025**, unabhängig von jeder Risikoklasse.

**System:** ___  **Schulung am:** ___  **Durchgeführt von:** ___  **Dauer:** ___

### Inhalt

Eine Teilnahmeliste ohne Inhaltsangabe belegt Anwesenheit, nicht Kompetenz. Was vermittelt wurde:

- [ ] wie **dieses** Modell typischerweise irrt, mit Beispielen aus dem eigenen Haus
- [ ] woran eine falsche Ausgabe erkennbar ist
- [ ] was man damit tun darf: übergehen, korrigieren, eskalieren — und an wen
- [ ] was nicht hineingegeben werden darf
- [ ] wohin eine Fehlfunktion gemeldet wird

Weitere Inhalte: ___

### Teilnehmende

| Name | Rolle | Bedient das System | Beaufsichtigt Ausgaben | Teilgenommen |
|---|---|---|---|---|
| | | | | |

### Vollständigkeit

| Frage | Antwort |
|---|---|
| Wer bedient dieses System? (aus dem Inventar) | |
| Davon geschult | |
| Noch offen — mit Termin | |
| Wiederholung geplant für | |
| Bei Modellwechsel: Schulung geprüft? | |

Die letzte Zeile wird übersehen: Eine Schulung, die erklärt, wie das alte Modell irrt, passt nach einem Modellwechsel nicht mehr.

**Eine allgemeine KI-Schulung erfüllt diesen Punkt nicht.** Art. 4 verlangt Kompetenz im Hinblick auf die eingesetzten Systeme.

## 3 Kennzeichnungsnachweis (Art. 50)

Anwendbar seit **2.8.2026**, unabhängig von der Risikoklasse.

**System:** ___  **Produktversion:** ___  **Geprüft am:** ___  **Geprüft durch:** ___

### Welcher Fall greift

| Fall | Trifft zu | Pflicht |
|---|---|---|
| direkter Kontakt mit Menschen (Chat, Sprachassistent) | | Hinweis, dass es KI ist |
| erzeugte oder bearbeitete Inhalte (Text, Bild, Ton, Video) | | maschinenlesbare Kennzeichnung |
| Emotionserkennung, biometrische Kategorisierung | | Betroffene informieren |
| Deepfake | | offenlegen |

### Umsetzung je Ansicht

| Ansicht | Hinweis vorhanden | Vor der ersten Eingabe sichtbar | Nachweis |
|---|---|---|---|
| Desktop | | | |
| Mobil | | | |
| eingebettet | | | |
| E-Mail, Benachrichtigung | | | |

Die Mobilansicht ist der häufigste Einzelfehler: Eine überarbeitete Oberfläche verliert den Hinweis dort zuerst.

### Nachweis

| Feld | Eintrag |
|---|---|
| Art des Nachweises | Bildschirmaufnahme / Oberflächentest / Code-Verweis |
| **Produktversion** | |
| Datum | |
| Fundort | |
| Erstellt durch | |

Ohne Produktversion belegt eine Bildschirmaufnahme, dass es einmal so aussah — nicht, dass es im geprüften Stand so ist.

### Fortschreibung

- [ ] Die Prüfung ist Teil der **Releasefreigabe**, nicht eine Jahresaufgabe
- [ ] Bei jeder Oberflächenänderung wird neu geprüft
- [ ] Bei jeder neuen Funktion mit erzeugten Inhalten wird neu geprüft

## 4 Nachweisregister

Je System oder je Einsatzzweck. Verbindet Pflichten mit Belegen.

**Gegenstand:** ___  **Rechtliche Klasse:** ___  **Stand:** ___

| Pflicht | Rechtsgrundlage | Nachweis | Version | Zustand | Durch | Datum | Fundort |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

**Zustände:** offen (noch nicht erbracht, mit Person und Termin) · erbracht (liegt vor, niemand hat nachgesehen) · geprüft (eine zweite Person hat inhaltlich nachgesehen) · freigegeben (mit Versionsbezug bestätigt)

Und **zurück auf offen**, wenn eine neue Version läuft. Dieser Rückweg muss möglich sein, sonst veraltet das Register lautlos.

### Pflichten, für die eine Reihe und nicht ein Einzelstück der Nachweis ist

| Gegenstand | Nachweis ist |
|---|---|
| Beobachtung nach dem Inverkehrbringen (Art. 72) | die Reihe der Berichte |
| Auslöserprüfung | das Protokoll, einschließlich der Zeilen ohne Ergebnis |
| Testsätze gegen den Modellwechsel | die Folge der Durchläufe |
| menschliche Aufsicht (Art. 14) | die Reihe der Kennzahlen über geänderte Ausgaben |

Ein einzelner aktueller Bericht belegt hier nichts: Er kann am Vortag der Prüfung entstanden sein.

### Probe

| Feld | Eintrag |
|---|---|
| Angeforderter Nachweis | |
| Zeit bis zur Vorlage | |

Dauert es länger als eine Stunde, ist der Nachweis in einer echten Prüfung nicht vorlegbar. Die Probe ist in zehn Minuten gemacht und sagt mehr als jede Vollständigkeitszählung.
